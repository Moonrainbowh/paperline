# Research Positioning：从研究内容识别学术定位

用于模式 A 的 Step 1–2，也用于模式 B 的完整稿件诊断。目标是找出研究可以进入的学术社区，而不是把论文压成一个宽泛的 `research_field`。

## 1. 研究理解清单

从论文、摘要、提纲、实验记录或作者说明中提取：

| 要素 | 要回答的问题 |
| --- | --- |
| 研究对象 | 研究什么材料、系统、工程设施或数据？ |
| 核心问题 | 要解释、预测、设计、控制或优化什么？ |
| 场景 | 哪种工程或科学应用使这个问题重要？ |
| 方法 | 实验、数值模拟、机器学习、优化、现场监测如何组合？ |
| 证据 | 数据来源、工况覆盖、基线、验证和不确定性是什么？ |
| 结果 | 得到什么定量结论、机制解释或工程收益？ |
| 贡献 | 新机理、新方法、新数据、设计工具还是决策支持？ |
| 成熟度 | 想法、部分结果、完整稿件、可投稿稿件？ |

先形成一句话临时研究画像；缺少非关键字段时继续分析，只标注不确定性。只有会改变候选集合的缺失信息才需要优先询问。

## 2. 多个 Research Positioning

为当前研究提出 2–4 个定位，每个定位写清：

- 它强调的科学或工程问题；
- 对应读者和学术社区；
- 适合检索的关键词组合；
- 可能对应的期刊类型；
- 当前稿件能否用现有证据支撑；
- 为什么是主要、次要或边缘定位。

常见交叉定位示例：

- 地下能源储存：关注储存安全、运行和完整性；
- 岩土/地下工程：关注围岩、盐岩、稳定性和工程设计；
- 数值模拟：关注模型、机理、参数和验证；
- 机器学习代理模型：关注预测、泛化、物理约束和基线；
- 工程优化：关注决策变量、约束、目标和可实施性；
- AI for Engineering：关注可解释、可复现和跨工况工程收益。

这些是检索与叙事入口，不是互斥分类，也不是评分维度。主要定位应由核心问题和证据决定，而不是由方法名称决定。

## 3. 模式 B 的完整稿件诊断

完整论文到达时，逐项检查 Title、Abstract、Introduction、Methods、Results、Discussion、Conclusion、Figures/Tables 和 References：

- 论文实际主张的研究定位是否与标题、摘要和结果一致；
- 主要贡献是科学问题、工程问题还是方法本身；
- 证据强度是否足以支撑当前定位；
- 方法、指标和图表是否服务于主问题；
- References 主要连接了哪些学术社区和期刊；
- 当前写法是否已偏向某个目标期刊或读者。

不要只按作者自称的领域分类。若参考文献集中在某期刊或研究社区，只把它作为发现线索，再用近年正式论文核对是否仍然持续。
