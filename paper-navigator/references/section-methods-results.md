# 方法、实验设计与结果的中文写作规则

用于工程、实验、数值模拟和方法类研究论文。方法回答“怎样得到可核验结果”，结果回答“在什么条件下观察到什么”。

## 方法章节

### 章节任务

使同行能够理解研究逻辑、评估有效性并在合理范围内复现关键步骤。不要为了叙事流畅而省略会改变结果的条件、参数或排除规则。

### 默认结构

```text
任务与范围
→ 数据/材料/工况
→ 总体技术路线
→ 各模块或研究步骤
→ 实现与参数
→ 实验/评价设计
→ 假设、复现范围和边界
```

| 小节/段落 | 必须回答 |
| --- | --- |
| 任务定义 | 研究对象、输入、输出、变量、单位、目标和排除范围是什么 |
| 数据/材料 | 来源、时间/空间范围、样本、筛选、预处理、划分、缺失和泄漏控制是什么 |
| 总体路线 | 各阶段怎样连接，哪些输入产生哪些中间量和最终输出 |
| 模块/步骤 | 为什么需要、怎样工作、关键设定、输出和与后续步骤的关系 |
| 实现细节 | 软件、版本、硬件、随机性、参数、停止准则和重复次数是什么 |
| 评价设计 | 研究问题、对照/基线、指标、统计方法、公平比较和不确定性怎样定义 |
| 复现与边界 | 哪些材料可用，哪些条件固定，哪些范围尚未验证 |

### 方法总览段

推荐句子功能链：

```text
研究对象与任务
→ 输入和输出
→ 总体流程及阶段关系
→ 每阶段解决的问题
→ 验证方式和范围
```

有技术路线图时，正文必须解释图的逻辑，不只写“流程见图X”。没有必要画图时，用文字版输入—处理—输出合同替代。

### 模块或步骤段

每个关键模块至少覆盖：

1. **目的**：该模块解决哪个明确问题，为什么显而易见的替代方案不够。
2. **输入**：输入变量、形状、单位、来源和先决条件。
3. **操作**：算法、试验、方程、流程或处理动作。
4. **设定**：会影响结果的参数、阈值、边界条件、初始化和随机性。
5. **理由**：设计选择如何对应研究问题或技术限制。
6. **输出**：产生什么，并怎样进入下一步骤或评价环节。

推荐功能链：

`【问】模块问题 → 【法】输入与操作 → 【定】参数/边界条件 → 【释】选择理由 → 【法】输出与衔接 → 【界】假设`

### 不允许的模糊表达

- “采用常规方法处理”——写出实际流程和判据。
- “使用默认参数”——列出会影响结果的默认值及来源。
- “进行了统计分析”——写明假设、统计量、检验、阈值和多重比较处理。
- “随机划分/随机分配”——说明随机化单位、比例、种子或过程。
- “模型得到验证”——把验证问题、数据、基线、指标和结果留给评价设计与结果章节。
- “其他设置保持不变”——列出对比较公平性关键的设置。

## 实验与评价设计

每组实验先写实验合同，再写结果：

| 字段 | 内容 |
| --- | --- |
| 实验ID | 稳定编号 |
| 研究问题/假设 | 本实验要区分什么或检验什么 |
| 数据/材料/工况 | 适用范围和样本 |
| 变量与控制 | 自变量、因变量、控制变量和排除项 |
| 比较对象 | 基线、标准方法、对照组或理论值 |
| 公平性 | 统一预算、输入、划分、调参规则和停止条件 |
| 指标 | 定义、单位、方向及选择理由 |
| 不确定性 | 重复、误差、区间、统计或敏感性分析 |
| 对应贡献 | 支撑哪项贡献 |
| 失败判据 | 什么结果会否定或削弱主张 |

方法章节写设计，不提前写观察结果；结果章节不得使用方法中未定义的数据、指标或比较对象。

## 结果章节

### 章节任务

按研究问题、贡献或证据阶梯呈现观察结果，而不是按照图1、图2、图3机械排列。每个主要主张都必须能回溯到表格、图件、统计输出或其他核验材料。

### 默认证据阶梯

```text
数据/系统/模型可信度
→ 主要结果
→ 公平基线比较
→ 消融、敏感性或机制证据
→ 泛化、应用或尺度变化
→ 稳健性、异常和失效条件
```

不适用的阶梯可以跳过，不能为凑结构虚构实验。

### 结果小节合同

| 字段 | 内容 |
| --- | --- |
| 小节问题 | 本节回答什么 |
| 核心结果句 | 最重要的观察是什么 |
| 证据锚点 | 图、表、统计输出、日志或原始记录 |
| 比较对象 | 与谁比较，条件是否一致 |
| 不确定性 | 样本、误差、区间、重复或敏感性 |
| 支持主张 | 支持贡献合同中的哪一项 |
| 不支持 | 哪些更强解释不能由本结果得出 |
| 边界 | 结果适用于哪些数据、工况或条件 |

### 结果段句子序列

```text
RES-1 验证问题或本段有限主张
RES-2 数据、工况、对照和评价条件
RES-3 主要观察与定量结果
RES-4 基线比较、效应量、误差或统计证据
RES-5 异常、例外、敏感性或稳健性
RES-6 本段能够支持的局部结论与边界
```

示意句式只用于填入真实数据：

```text
在【数据/工况】和【统一比较条件】下，【方法/对象】的【指标】由【基线值】变为【结果值】，相对变化【比例】；该结果支持【限定结论】，但尚不覆盖【未验证范围】。
```

### 结果与讨论的边界

结果中可以写短的、紧邻证据的局部判断，但不要扩展为长机制推测：

- 结果：观察到了什么、条件是什么、数值和不确定性是什么。
- 讨论：为什么可能出现、与已有研究怎样对应、替代解释是什么、何时可能失效。

若结果段出现“可能源于、这说明普遍、可广泛应用”等表达，检查是否应移入讨论。

### 常见失败

- 逐图描述，没有研究问题和局部结论。
- 只报告最优结果，隐藏失败、异常或不利条件。
- 裸百分比、无单位、无样本量、无基线或无统一工况。
- 用测试集、最终评价或事后选择反向指导模型选择，却不披露。
- 把统计显著性等同于工程重要性。
- 每段有主张但没有证据锚点。
- 结果中的指标、数据或方法在方法章节从未定义。
- 用“充分证明优越性”替代限定结论。

## 结果与讨论合并结构

目标期刊或学科采用合并章节时，每个主题单元按以下顺序写：

```text
研究问题
→ 方法/条件提醒
→ 结果证据
→ 比较与不确定性
→ 解释或机制
→ 与已有研究对话
→ 替代解释和边界
→ 局部结论
```

内部仍用 `【据】` 和 `【释】` 区分事实与推断。不得因为章节合并就省略总体讨论中的跨结果综合、局限和工程代价。

## 章节质量门

### 方法通过条件

- 关键结果都能找到对应的方法来源。
- 数据、划分、排除、预处理、参数和统计设计足以评估有效性。
- 基线与本文方法的比较规则公平且透明。
- 技术路线中的每个关键步骤都有输入、操作、输出和理由。
- 不把未提供或未核验的信息写成既定事实。

### 结果通过条件

- 每项核心结果有证据锚点、条件、指标、比较和边界。
- 数字与图表、表格和原始输出一致。
- 失败、异常和不确定性没有被语言隐藏。
- 结果不超出实验合同，讨论性推断没有伪装成观察事实。
- 所有引言贡献至少有一项方法支撑和一项结果证据；没有证据的贡献降级或删除。
