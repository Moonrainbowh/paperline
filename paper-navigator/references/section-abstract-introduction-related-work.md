# 标题、摘要、引言与相关工作的中文写作规则

用于论文前部章节。段落数和句数是默认建议，不是评分指标；证据和叙事需要优先。

## 标题与关键词

标题只承诺正文已经证明或支持的范围。优先采用：

```text
研究对象/系统 + 方法、能力或核心发现 + 应用情境或边界
```

规则：

- 标题应具体、可检索、可由正文证据支持，不写宣传口号。
- 数字、性能词或因果词出现在标题中时，逐项核对正文。
- 避免“关于……的研究、面向未来、开启新纪元、先进/高效/智能”等无具体比较对象的表达。
- 先生成3—5个候选，可覆盖对象导向、方法导向、结果导向；标记最稳妥候选及理由。
- 标题可以早拟，但只有摘要和全文稳定后才能锁定。

关键词应覆盖研究对象、核心方法、主要任务或场景；不重复堆叠标题中的同义词，也不加入正文没有展开的热点词。

## 摘要

### 章节任务

用独立、可核验的一段文字压缩整篇论文，使读者知道为什么做、缺什么、做了什么、证据是什么、意味着什么、适用于哪里。摘要最后定稿。

### 默认句子功能序列

| 句位 | 功能 | 写作要求 |
| --- | --- | --- |
| ABS-1 | 对象与问题 | 直接点明研究对象和具体科学/工程问题，不从宏大口号起笔 |
| ABS-2 | 精确缺口 | 说明现有方案在什么条件下不能满足什么要求 |
| ABS-3 | 目的或核心洞见 | 写本文要回答的问题；必要时给出促成方法的关键观察 |
| ABS-4 | 方法概述 | 说明建立、提出、分析或验证了什么，不堆模块细节 |
| ABS-5 | 验证设计 | 交代数据、试验对象、工况或主要比较框架；篇幅紧时可并入ABS-6 |
| ABS-6 | 决定性结果 | 给出最支撑主旨的结果，包含条件、比较对象、指标和数值 |
| ABS-7 | 补充证据 | 写泛化、稳健性、消融、机制或工程效益；没有可靠证据就删除 |
| ABS-8 | 意义与边界 | 说明新增能力或认识，并限定适用范围和未验证范围 |

### 论文类型变体

| 类型 | 功能链 |
| --- | --- |
| 方法/算法型 | 任务 → 技术挑战 → 核心洞见 → 方法 → 比较设计 → 性能证据 → 边界 |
| 工程应用型 | 工程问题 → 现有方案限制 → 系统/方案 → 工况与数据 → 效果 → 工程价值与使用条件 |
| 实验发现型 | 科学问题 → 未知点 → 实验设计 → 关键观察 → 解释证据 → 科学含义与边界 |
| 数值模拟型 | 研究对象 → 建模缺口 → 模型/工况 → 校核方式 → 关键规律 → 敏感性/适用条件 |

多贡献型摘要只有在贡献真正并列且各有证据时才采用；不要为了显得丰富而列出多个功能特征。

### 常见失败

- 摘要先写后不再更新，最终与结果和讨论不一致。
- 只有方法名称和“效果良好”，没有决定性证据。
- 出现正文没有论证的新结果、机制或应用承诺。
- 用裸百分比或“显著提升”替代条件、基线、指标和数值。
- 结尾只写“具有重要意义和广阔前景”。
- 默认堆放引用；除非目标期刊明确要求或允许，摘要通常不引文。

## 引言

### 章节任务

让读者接受完整推理链：问题值得研究，已有工作仍留下明确缺口，本文路线直接回应缺口，而且引言承诺都能由方法和结果兑现。

最终引言通常4—5段。第0版只锁定叙事；方法、结果、讨论和相关工作稳定后重写最终版。

### 默认段落蓝图

| 段落 | 唯一任务 | 推荐句子功能序列 |
| --- | --- | --- |
| P1 研究对象与价值 | 说明研究什么、为什么值得关心 | 定义对象/场景 → 科学或工程价值 → 核心性能要求/现实后果 → 收束到具体困难 |
| P2 主流路径与瓶颈 | 建立必要背景，不做文献清单 | 定义主流路线 → 共同机制 → 已有进展及引用 → 特定条件下的限制 → 限制来源或证据状态 |
| P3 最近工作与精确缺口 | 把宽泛不足压缩成可验证问题 | 最接近路线 → 已解决内容 → 未覆盖对象/条件/能力 → 可验证缺口 → 缺口重要性 |
| P4 本文问题、洞见与路线 | 正面回答准备怎样处理缺口 | 承接缺口 → 研究问题/目标 → 核心洞见或假设 → 总体方法/实验路线 → 研究范围 |
| P5 贡献与证据预告 | 给出正文承诺 | 总贡献 → 各项贡献的动作、新增能力和证据位置 → 必要边界 → 可选全文结构 |

贡献句采用：

```text
研究动作 + 新增的知识或能力 + 由什么证据验证 + 适用边界
```

“提出模型、搭建平台、开展实验”只是动作，不自动构成贡献。

### 结构变体

- 任务陌生：先定义输入、输出、对象和范围，再谈应用价值。
- 任务熟悉：从具体工程痛点、失效场景或关键矛盾切入。
- 新任务：采用“母任务 → 相邻方法 → 新任务独有挑战 → 本文定义和验证”。
- 单一关键模块：采用“已有框架 → 关键观察 → 新模块 → 为什么能够解决限制”。
- 已有独立相关工作：引言只保留建立缺口必需的文献，避免重复完整综述。
- 期刊不接受贡献列表：改写为连贯段落，但内部仍保留贡献—证据映射。

### 常见失败

- 第一段是行业口号，读者迟迟不知道研究对象。
- 按年份或作者逐篇介绍文献，没有形成方法类别和技术矛盾。
- “仍缺乏研究”没有检索范围和引用支持。
- 把作者推测写成已有方法失败的既定原因。
- 只堆方法模块名，不解释其如何回应缺口。
- 把实现细节、功能列表或实验步骤当作创新点。
- 承诺泛化、机制或工程价值，但结果章节没有对应证据。
- 最终引言沿用早期设想，没有根据真实结果降低或删除主张。

## 相关工作

### 章节任务

公平定位本文与最相关研究路线的关系，使“继承了什么、差别在哪里、尚缺什么”可以核查。

默认先确定2—4个技术主题，每个主题一段；资料密集时拆为“主流方法段”和“最接近工作段”。

| 段落类型 | 推荐句子功能序列 |
| --- | --- |
| 范围段（可选） | 界定范围 → 说明纳入理由 → 声明比较轴，如机制、输入、假设、数据、性能或场景 |
| 主题段 | 定义方法族和共同目标 → 概括机制/假设 → 代表性进展及引用 → 内部差异 → 与本文问题相关的能力边界 |
| 最接近工作段 | 明确最强相关路线 → 相同点 → 按统一比较轴说明差异 → 仍未解决的问题 |
| 综合定位段 | 各路线解决了什么 → 共同权衡/剩余缺口 → 本文归属或区别 → 差异落到任务、机制、假设或评价设计 |

工程、实验、数值模拟和方法类论文可以按下列主题组织：

- 机理或传统方法；
- 实验或数值方法；
- 数据驱动、混合或本文最接近的方法；
- 工程验证、数据资源或评价协议。

文献很少或目标期刊要求合并时，将必要内容并入引言P2—P3，不强制单设章节。

### 常见失败

- “作者A做了……作者B做了……”式文献目录。
- 每段都说“存在不足”，却不说明条件、机制或证据。
- 回避最强竞争方法，或用弱化、过时基线抬高本文。
- 把综述论文当作全部原始结论的唯一来源。
- 把基础组件与直接竞争方法混为一类。
- 与引言重复相同文献和相同表述。
- 使用不可核验的“首次、从未研究”。
- 所述局限并非来源原文、可靠复现或公平实验所得。

## 章节质量门

| 章节 | 进入中文定稿的必要条件 |
| --- | --- |
| 标题/关键词 | 范围不宽于正文；核心术语可检索且全文一致；没有未经证实的性能或因果词 |
| 摘要 | 每个实质句可定位到正文；关键结果有条件和比较对象；没有新增主张；意义与讨论/结论一致 |
| 引言 | 缺口有来源；贡献逐项映射方法和结果；未承诺未验证能力；第0版已被最终版替换 |
| 相关工作 | 强相关路线未遗漏；引用支持具体陈述；比较轴一致；局限表述公平；与引言不重复 |

最低跨章节映射：

```text
摘要问题 = 引言缺口
摘要方法 = 引言贡献 = 方法章节动作
摘要关键结果 = 结果章节证据
摘要意义 = 讨论/结论解释
相关工作中的缺口 = 本文设计选择或验证问题
```
