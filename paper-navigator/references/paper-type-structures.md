# 综述、纯理论与技术路线专用结构

当论文不是默认的工程、实验、数值模拟或方法型实证论文，或者用户单独要求“写技术路线”时，使用本文件。先判断结构合同，再调用通用中文句子规则、反向提纲和质量门；不得把实证论文的章节模板机械套用到其他类型。

## 类型判定

先看中心主张由什么证据成立：

| 类型 | 中心主张的主要依据 | 不应强制使用 |
| --- | --- | --- |
| 工程/实验/数值模拟/方法型 | 数据、实验、模型结果、比较或验证 | 无 |
| 系统综述/范围综述 | 可复现检索、筛选、质量评价和证据综合 | 原始实验式技术路线、消融模板 |
| 叙述性/批判性综述 | 透明的范围、来源选择与概念/主题综合 | 未执行却声称系统综述的流程 |
| 纯理论/定理证明型 | 定义、假设、逻辑推演、证明、反例和推论 | 实验结果、基线、统计显著性或消融 |
| 混合型 | 理论命题与实证证据各自承担不同主张 | 用实验“证明”数学命题，或用定理替代经验验证 |

类型不清且不同选择会改变证据合同或章节结构时，给出候选类型、判断依据和最多三个高影响问题，请作者确认。类型已清楚时直接路由。

## 综述论文结构

### 先锁定综述合同

```text
综述类型：系统 / 范围 / 叙述性 / 批判性 / 其他
核心综述问题：
对象与概念边界：
时间、语言和来源范围：
纳入/排除原则：
检索与更新日期：
质量评价方式：
综合单位和比较轴：
允许得出的结论：
不能声称的完整性或因果结论：
```

如果没有可复现检索、筛选记录和相应报告过程，不得将叙述性检索写成“系统综述”或声称全面覆盖。

### 默认章节与段落功能

| 章节/段落 | 唯一任务 | 推荐句子功能序列 |
| --- | --- | --- |
| 引言 P1 | 界定对象与重要性 | 定义对象 → 说明科学/工程后果 → 收束综述范围 |
| 引言 P2 | 概括现有认识和争议 | 已有共识 → 关键分歧/缺口 → 为什么需要本综述 |
| 引言 P3 | 提出综述问题和贡献 | 精确问题 → 分析框架/比较轴 → 预期综合贡献 → 边界 |
| 方法/范围 | 说明来源如何进入综合 | 数据库/来源 → 检索与日期 → 筛选 → 质量评价 → 综合方法；叙述性综述如实写透明范围，不伪装系统流程 |
| 主题综合段 | 综合一个主题而非罗列论文 | 主题判断 → 多来源证据 → 一致与差异 → 差异条件/质量 → 局部结论和边界 |
| 跨主题比较段 | 解释方法族或证据群关系 | 统一比较轴 → 相同点 → 差异与权衡 → 适用情境 |
| 争议/缺口段 | 区分未知与证据不足 | 争议命题 → 正反证据 → 证据质量/异质性 → 当前不能回答什么 |
| 研究议程 | 把缺口转成可验证问题 | 缺失证据 → 需要的设计/数据 → 可判定结果 → 优先级依据 |
| 结论 | 回答综述问题并限定范围 | 综合答案 → 最稳健认识 → 关键争议 → 使用边界 |

主题段不得按“作者A做了……作者B做了……”逐篇堆叠。每个综合判断都要映射到纳入来源、来源质量和适用范围；负面或冲突证据不得静默删除。

### 综述质量门

- 综述问题、检索/选择范围和结论范围一致。
- 系统/范围综述的数据库、检索式、日期、筛选、排除理由和质量评价可追踪。
- 叙述性/批判性综述明确来源选择边界，不声称穷尽全部文献。
- 主题综合使用统一比较轴，区分来源结论、作者综合和未来假设。
- 关键结论不是由单篇论文、二手转引或标题/摘要匹配支撑。
- 冲突证据、研究异质性、发表偏倚或证据质量限制已经显式讨论。
- 研究议程由已识别缺口推出，不是泛化愿望清单。

## 纯理论论文结构

### 先锁定理论合同

```text
研究对象与问题域：
原始定义和既有定义：
符号体系：
基本假设及必要性：
中心命题/定理：
证明策略：
依赖的引理或既有定理：
反例、极端情形和适用边界：
理论新增认识：
可选数值/实例说明的地位：说明而非证明
```

定义、假设或符号尚未稳定时，不先润色定理表述。引用既有定理必须核对原始条件；不得只凭名称推定可用。

### 默认章节与段落功能

| 章节/段落 | 唯一任务 | 推荐句子功能序列 |
| --- | --- | --- |
| 引言问题段 | 提出理论问题和意义 | 问题域 → 已有理论能力 → 精确缺口 → 解决该缺口的意义 |
| 引言贡献段 | 预告新增命题和条件 | 中心命题 → 相对已有结果的变化 → 证明思路 → 适用边界 |
| 预备知识 | 锁定定义、符号和依赖 | 定义 → 符号 → 已知结果及来源 → 本文使用条件 |
| 假设段 | 说明推导起点 | 假设 → 数学/物理含义 → 必要性 → 不满足时的后果 |
| 命题/定理段 | 给出可判定陈述 | 条件 → 精确结论 → 量词/范围 → 与相邻命题关系 |
| 证明段 | 建立完整推理链 | 证明目标 → 分解步骤 → 每步依据 → 中间结论 → 闭合目标 |
| 反例/边界段 | 说明结论停止位置 | 放松的条件 → 反例或失效 → 受影响结论 → 最小必要条件 |
| 推论/意义段 | 说明新增认识 | 由定理推出的结果 → 与既有理论关系 → 可解释含义 → 边界 |
| 结论 | 闭合理论问题 | 中心结果 → 关键条件 → 理论意义 → 未解决问题 |

若包含数值算例、模拟或实验，只能把它们标记为说明、检验直觉或展示适用情境；除非中心经验主张另有实证合同，否则不能用有限案例替代一般性证明。

### 理论质量门

- 每个符号先定义后使用，同一符号不承担冲突含义。
- 每条定理完整给出条件、量词、定义域和结论。
- 每个证明步骤能回溯到定义、假设、已证引理或已核验的既有定理。
- 不存在循环论证、隐含假设或从例子跳到一般命题。
- 关键假设的必要性、可弱化性和失效后果已经检查。
- 与最接近理论结果的差异按条件和结论比较，不用“首次”替代证明。
- 反例、边界或极端情形与主张强度一致。
- 摘要和结论不把“在给定假设下成立”扩大为无条件普遍成立。

## 技术路线文字与图件

技术路线先是文字论证合同，之后才是流程图。用户说“写技术路线”时，读取本文件、`manuscript-finalization-workflow.md` 和 `section-methods-results.md`；用户说“画技术路线图”时，在文字合同稳定后再调用 `figure-planning-qa.md` 或制图 Skill。

### 技术路线文字合同

| 步骤ID | 要回答的问题 | 输入 | 研究动作/方法 | 输出 | 支撑的主张 | 验证方式 | 失败或停止条件 | 下一步 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

每一步必须说明“为什么存在”和“怎样验证”，不能只列软件、模型或实验名称。分支、迭代、数据排除、参数选择和停止条件如会改变结果，也必须进入路线。

### 技术路线段落功能

1. **目标句**：说明整条路线要回答的研究问题，而不是只写“开展研究”。
2. **输入与边界句**：定义材料、数据、工况、假设和已知限制。
3. **动作链句**：按依赖顺序写每项研究动作及其输出，说明前一步如何成为后一步输入。
4. **验证句**：把每项核心主张映射到比较、实验、统计、理论检查或工程判据。
5. **停止与失败句**：说明何种结果会否定、削弱或终止当前路线。

图中每个节点必须能回到文字合同的一行；图中不得新增正文没有定义的方法、数据流或结论。视觉路线图只负责压缩关系，不替代方法细节和证据链。

## 与19步主线的关系

- 工程、实验、数值模拟和方法型论文使用完整19步主线。
- 综述论文保留主题、主旨、贡献、结构、引言、摘要、反向提纲、一致性和质量门；将“技术路线—方法—结果—讨论”替换为“综述合同—检索/选择—质量评价—主题综合—争议与议程”。
- 纯理论论文保留主题、主旨、贡献、结构、引言、摘要、反向提纲、一致性和质量门；将实证中段替换为“理论合同—定义/假设—命题—证明—反例/边界—推论”。
- 混合型论文为不同主张分别维护理论证据和实证证据，最后在主张合同中闭环；不能让一种证据类型越权替代另一种。
- 所有类型仍执行 `S0—S7` 状态和中文定稿硬门；不适用的门必须给出理由并标记 `not-applicable`，不得直接跳过。
