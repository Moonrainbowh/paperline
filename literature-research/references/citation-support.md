# 引用支持

把段落拆成原子主张，判断每项主张需要什么来源，再检查来源的阅读状态和正文锚点。

可使用的简单等级：`direct`、`partial`、`background`、`conflict`、`not-supporting`。如果来源只能部分支持，就收窄措辞；没有支持来源时明确标记缺口，不用主题相似的论文掩盖缺证据。

## 共享证据卡

证据卡是 `literature-evidence.md` 中的主张级条目，不另建一份需要同步的文献池。已有同类文件时沿用其路径和编号，增量补充：

| 字段 | 应写内容 |
| --- | --- |
| 主张及编号 | 一条可单独判断的原子主张；可沿用已有主张编号 |
| 来源与元数据 | 题名、作者、年份、已核验 DOI 或稳定链接；未知项写待核，不补造 |
| 阅读状态 | `metadata-only`、`abstract-read`、相关正文已读或全文已读；说明实际覆盖范围 |
| 原文位置 | 页码、章节、图表、公式或可唯一定位的段落；无法回查写“待定位” |
| 摘录及语境 | 关键原文或忠实概括，保留对象、条件和限制；摘录遵守来源的引用限制 |
| 支持范围 | 在什么对象、条件和强度下支持这条主张，采用上面的支持等级 |
| 不支持范围 | 不能由该来源推出的因果、数值、机制、对象或泛化范围 |
| 待补项 | 缺全文、缺位置、元数据冲突、相反证据或需要再检索的方向 |

文献元数据核验、原文定位和科学支持是不同判断。题名或 DOI 匹配不代表读过正文，定位到一句话也不代表它支持当前推断。作者采纳某种解释只能记录为作者决定，不能升级来源支持等级。

交给章节写作或审查时，提供可复用的条目编号、来源锚点和证据边界。收到缺证据的句子时先检查当前池，再按缺口补源；不重新开展与本轮无关的全量检索。
